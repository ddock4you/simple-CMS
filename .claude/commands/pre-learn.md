현재 대화에서 계획된 개발 내용을 분석하여 **사전학습 문서**를 생성해줘.

## 동작 순서

1. **주제 파악**: 현재 대화에서 계획 단계에서 논의된 기술, 패턴, 도구를 파악하고 주제명을 결정해 (예: "모노레포", "DB-인증", "SSR-SEO"). Stage 번호가 없는 횡단/실전/트러블슈팅 주제는 `특별편-` prefix를 사용해 (예: `특별편-시연배포실전-...`, `특별편-Prisma7-config-스키마진화-...`)
2. **기존 문서 중복 확인**: `docs/learning/{1-design,2-develop}/` 디렉토리에 동일 주제 또는 유사 키워드(`특별편-` 시리즈 포함)의 사전학습 파일이 이미 있는지 검색. 중복이면 새로 만들지 말고 **기존 문서를 업데이트**하거나, 새 문서를 만들 때는 기존 문서와의 **관계(보완/심화/실전 후속)를 첫 문단에 명시**. 같은 주제로 두 문서가 평행 존재하지 않도록 함
3. **프로젝트 컨텍스트 확인**: 루트 CLAUDE.md, apps/\*/CLAUDE.md, docs/ 설계 문서에서 해당 주제가 이 프로젝트에서 어떻게 쓰이는지 확인
4. **최신 문서 참조**: 관련 라이브러리가 있으면 Context7 MCP로 최신 공식 문서를 참조
5. **사전학습 문서 생성**: 아래 템플릿에 맞춰 `docs/learning/{1-design|2-develop}/{주제}-사전학습.md` 파일 생성. 실전 함정/운영 디버깅 영역은 `2-develop/특별편-...` 위치
6. **README 업데이트**: `docs/learning/README.md`의 문서 목록에 추가 (Stage 번호가 없는 특별편은 별도 표 또는 "추가 학습" 섹션에 정리)

## 템플릿

```markdown
# 사전학습: {주제}

## 이 주제에서 다루는 기술

- 기술명 — 한 줄 설명 (역할)

## 핵심 개념

### {개념 1}

#### 정의

한 줄로 이 개념이 무엇인지.

#### 동작 원리

내부적으로 어떻게 작동하는지 구체적으로 설명. 단순 "이런 도구다"가 아니라 "내부에서 이런 과정을 거친다"를 보여줘.

#### 이 프로젝트에서의 적용

Simple CMS 프로젝트에서 이 개념이 어떤 역할을 하고, 왜 선택했는지.

### {개념 2}

(같은 구조 반복)

## 레거시 ↔ 모던 대조표

이 사용자는 레거시 환경에서 모던 프론트엔드로 전환 중. 각 개념에 대해 "이전에는 이렇게 했는데 지금은 이렇게 한다"를 대조해줘.

| 관점 | 레거시 환경에서는 | 이 프로젝트에서는 |
| ---- | ----------------- | ----------------- |
| ...  | ...               | ...               |

## 구현 시 주의할 점

- 이 기술을 처음 사용할 때 흔히 하는 실수
- 안티패턴
- 이 프로젝트 맥락에서 특히 주의해야 할 것

## 이 주제를 마치면 설명할 수 있어야 하는 것

면접에서 물어보면 답할 수 있는지 자기 검증용 체크리스트 (3-5개).

- [ ] {질문 형태}
- [ ] ...
```

## 작성 원칙

- 동작 원리를 설명할 때는 추상적 설명이 아니라 **구체적인 메커니즘**을 보여줘 (예: "pnpm은 심볼릭 링크를 사용한다" → pnpm이 node_modules를 어떻게 구성하는지 단계별로)
- 레거시 대조표는 사용자의 실제 경험(운영/유지보수/jQuery 환경)과 연결
- 기존 면접 문서(`docs/react-cms-면접-예상질문-모범답변집.md`)에 이미 있는 내용과 **중복하지 말고 보완** 관계를 유지
- 프로젝트 설계서(`docs/react-cms-개발-설계서.md`)의 선택 이유를 참조하되, 더 깊은 기술적 배경을 추가
