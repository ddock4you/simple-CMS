현재 대화에서 계획했던 내용과 실제 작성된 코드를 분석하여 **학습정리 문서**를 생성해줘.

## 동작 순서

1. **주제 파악**: 현재 대화의 계획 내용에서 주제명 결정. 같은 주제의 사전학습 문서(`docs/learning/{주제}-사전학습.md`)가 있으면 동일 주제명 사용
2. **구현 내용 분석**: 이번 세션에서 작성/수정된 코드, 설정 파일, 구조 변경을 분석
3. **기존 문서 참조**:
   - `docs/react-cms-면접-예상질문-모범답변집.md` — 답변 스타일 참조 (5-10문장, 선택 이유 → 트레이드오프 → 확장 가능성)
   - `docs/react-cms-실무-전환-관점-정리.md` — 레거시 경험 연결 포인트 확인
4. **학습정리 문서 생성**: 아래 템플릿에 맞춰 `docs/learning/{주제}-학습정리.md` 파일 생성
5. **README 업데이트**: `docs/learning/README.md`의 문서 목록에 추가

## 작성 원칙

- **코드로 보는 개념**: 일반적인 예제가 아닌 이 프로젝트의 실제 코드(파일 경로 포함)를 참조해서 설명
- **면접 Q&A**: 기존 면접 문서(`docs/react-cms-면접-예상질문-모범답변집.md`)와 동일한 톤과 구조. 이미 있는 질문은 중복하지 말고, 구현 경험에서 나올 수 있는 **새로운 질문**을 추가
- **트러블슈팅**: 대화 중 발생한 에러, 삽질, 설정 이슈 등을 기록. 면접에서 "실제로 문제를 만나본 적 있나요?" 대응용
- **한 줄 요약**: 면접 직전에 빠르게 훑을 수 있도록 핵심만 압축
- **레거시 연결**: `docs/react-cms-실무-전환-관점-정리.md`의 프레이밍("레거시를 부정하지 않고, 이번 프로젝트가 그 경험의 확장")을 유지
