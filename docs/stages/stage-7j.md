# Stage 7j — CI matrix + turbo 정리 + MSW 대신 fetch stub decorator + play function 2건 + addon-vitest 30초 timeout 탐사

Stage 7f~7i의 Storybook + Vitest 인프라 위에 **CI 자동화 + 보류된 mutation play function**을 얹는 정리 단계. 원안 4축 중 MSW 재도입은 primary source 확인 후 `window.fetch` stub decorator로 대체.

- **MSW 재도입 재조사 → fetch stub decorator 채택**: `npm view msw-storybook-addon versions --json`로 latest=2.0.7 (2026-04-08 릴리스), **v2.1 부재** 확인(canary/beta/next 태그 모두 v2.0.x). Stage 7h 실패 시점(2026-04-22)과 동일 버전 → 재시도 가치 없음. advisor 제안을 반영해 CLAUDE.md 원래 의도인 "play function으로 submit 성공/실패 분기 검증"은 MSW 대신 `window.fetch` 직접 stub으로 달성 (infra delta 0에 가까움)
- **`apps/admin/.storybook/fetchStubDecorator.ts` 신규**: Story `parameters.fetchMock: { [path-substring]: { status, body } }` 맵으로 window.fetch 일시 override. 응답 body는 admin fetchClient 표준(`{ success, data?, error? }`)에 맞춤. unmount 시 원본 복원. `useRef` + `useEffect` 패턴으로 re-render 안전. preview.tsx decorators 배열 맨 뒤(innermost)에 등록 — fetch stub이 Story에 가장 가까워 useEffect가 가장 먼저 실행되도록
- **CreateRoleDialog Submit Success / SubmitConflict play function**: `POST /api/roles`를 201(success)/409(conflict)로 분기. Success: Dialog 열기 → 이름 입력 → 저장 → "역할이 생성되었습니다" toast + **Dialog 닫힘**(waitFor 필요, 토스트는 `useMutation.onSuccess`에서 동기 실행, Dialog 닫힘은 `mutate()` 인라인 onSuccess에서 약간 지연). Conflict: 같은 플로우 + "이미 사용 중..." toast + **Dialog 열림 유지**(`getByText('새 역할 추가')` still visible). body portal 탐색은 `within(document.body)` (7h 규약)
- **SectionReorderProbe Reorder500 (rollback 검증)**: `useReorderHomeSections` 훅이 optimistic setQueryData + onError rollback을 수행하는 로직을 probe로 DOM 가시화. SectionList는 dnd-kit pointer 이벤트만 사용하고 화살표 버튼이 없어 Playwright 재현 불안정 → probe 컴포넌트 패턴(7h `PermissionProbe`/`DirtyGuardProbe` 선례) 채택. probe는 `useQuery(homeKeys.lists())` + `initialData: MOCK_SECTIONS` + `[상위 2개 교체]` 버튼 + `mutation-status` 상태 + `section-list` 렌더. 500 응답 시 `mutation-status='error'` 전환 + 토스트 "순서 변경에 실패했습니다" + `Section A` 여전히 맨 위(rollback 확인)
- **fetchStubDecorator 위치 결정 근거**: Storybook decorator 배열은 `reduceRight`로 적용되어 **첫 번째가 outermost, 마지막이 innermost**. fetchStub을 innermost에 두면 Story 컴포넌트 직외곽 wrapper가 되어 useEffect가 Story의 effect보다 먼저 실행됨 (React는 innermost부터 effect 실행). CreateRoleDialog는 submit 시점에만 fetch → 사실상 타이밍 무관, SectionReorderProbe도 initial fetch 없음(initialData로 cache 사전 populate) → outer/inner 무관하지만 방어적 설계
- **GitHub Actions CI matrix (`.github/workflows/ci.yml` 신규)**: `{admin, web}` × `{lint, typecheck, test}` 6 job 병렬. `pnpm/action-setup@v4`(v10.33.0) + `actions/setup-node@v4`(node 22 + pnpm cache) + `pnpm install --frozen-lockfile`. test job에만 `playwright install --with-deps chromium` 선행 (browser 모드 필수). `build-storybook`은 CI 제외(test project가 이미 story 로드/렌더 검증, 90s+ 추가 비용). `concurrency.cancel-in-progress: true for PR` (main push는 취소 금지)
- **`turbo.json` `test.dependsOn: ["^build"]` 제거**: Vitest는 소스 직접 실행 → 빌드 아티팩트 불필요. `test:coverage`는 별도 태스크라 이번에 안 건드림(YAGNI). 검증: `pnpm test` 실행 시 `@simple-cms/admin#build` 등이 선행되지 않음을 turbo log로 확인
- **addon-vitest 30초 timeout 탐사 결과(best-effort, revert)**: `vitest run` CLI의 setup time이 baseline 31.56s. `.storybook/main.ts`의 `viteFinal` 훅에 `optimizeDeps.include`(react, @tanstack/react-query, storybook/test, sonner, react-hook-form 등 11종) pre-warm 시도 → steady-state setup 30.84s(−0.7s, 노이즈 범위), config 변경 첫 실행은 37.56s(Vite "Re-optimizing dependencies" 페널티). **효과 불충분 + 첫 실행 회귀 → revert**. `storybookScript` 옵션은 Storybook UI "Run tests" 버튼 표면 전용이라 CLI/CI blast radius 밖(advisor 지적) → 미시도. 30s 근본 원인은 addon-vitest의 Storybook spin-up 자체로 보이며, Stage 7k 이후 조사 이연
- **검증**: admin 18 files / **56 tests** (52 → +4 = CreateRoleDialog 2 + SectionReorderProbe 2), web 12 files / **33 tests** 유지. 루트 `pnpm test` **총 89 tests 통과** (85 → +4), wall time 약 50s(turbo 병렬). CI는 최초 실제 PR에서 녹색 확인 예정
- **Stage 7j가 하지 않은 것**: MSW node 모드 setupServer(fetch stub으로 충분), Playwright E2E suite(Stage 8 이후), Coverage threshold/Codecov 연동, storybookScript 도입, web 앱 fetch stub(Server Component 중심이라 mutation play function 후보 없음)
- **선재 lint/typecheck 이슈 일괄 정리 (CI 도입 blocker 제거)**: Stage 7f 도입 이래 누적된 6건을 CI 전 일괄 수정 — Stage 7j 범위 외였으나 CI 진입을 위해 필요:
  - ESLint `storybook-static/**` globalIgnores 추가 (`packages/config/eslint/next.js`) → admin/web 각 10K+ 에러 해소 (bundled minified JS가 lint 대상이 되던 bug)
  - Decorator rules-of-hooks 회귀 정리: `rootDecorator`(preview.tsx)/`fetchStubDecorator`(신규)/`withMockRefs`(LinkTargetInput.stories) 모두 **hooks를 PascalCase 내부 컴포넌트**(`RootProviders`/`FetchStub`/`MockRefsProvider`)로 추출. 외부 decorator는 `<Inner>{children}</Inner>` 래핑만 담당. authenticatedDecorator는 hooks 미사용이라 변경 없음
  - `vite` devDep 명시 추가(admin/web `package.json` devDependencies에 `"vite": "^7.3.2"`) — `vite.config.ts`의 `import { defineConfig } from 'vite'` 타입 해결
  - `packages/config/vitest/{base,browser}.d.ts` shim 신규 — `@simple-cms/config/vitest/base.js` import의 TS7016 "Could not find declaration" 해소. 실제 값은 `.js`에 있고 `.d.ts`는 타입만 선언
  - web `SideNavigation.stories.tsx`의 `StoryObj<typeof meta>` 타입 에러(`args missing`) 해소: `placeholderArgs = { children: null }` 패턴 적용 (LinkTargetInput.stories 선례)
  - web `Header.stories.tsx` / `SubpageBlockRenderer.stories.tsx`의 TS2742/TS4023 "cannot be named" 에러 해소: `satisfies Meta<typeof X>` → `: Meta<ComponentProps<typeof X>>` 명시 주석. krds-react 내부 타입 + 비공개 `BlockInput` 인터페이스가 inferred type에 포함되면서 선언 portability 실패하던 것을 우회
  - web `SkipLink.stories.tsx`의 unescaped entity (`"..."` → `&ldquo;...&rdquo;`)
  - **검증**: `pnpm lint` / `pnpm typecheck` / `pnpm test` 모두 녹색, 총 **89 tests** 통과
